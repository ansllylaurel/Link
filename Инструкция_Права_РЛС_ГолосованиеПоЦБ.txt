ИНСТРУКЦИЯ ПО РУЧНОМУ ВНЕСЕНИЮ ИЗМЕНЕНИЙ В КОНФИГУРАТОРЕ
Тема: приведение документа "Осуществление права голоса по ценным бумагам" и регистра
сведений "ГолосованияНаСобранияхВладельцевЦенныхБумаг" к стандартам прав/РЛС конфигурации.

Код модулей (ObjectModule.bsl) вы переносите сами копированием, эта инструкция его не касается.
Ниже — только те изменения, которые нельзя скопировать текстом: свойства реквизитов/измерений
в палитре свойств и права ролей (в т.ч. ограничения доступа на уровне записей — РЛС).

Всего 3 блока:
  1. Свойства реквизитов документа.
  2. Свойства измерения регистра сведений.
  3. Права и РЛС в трёх ролях: ОперацииБэкОфиса, БазовыеПрава, ОперацииБэкОфисаПросмотр.

Важно: оба шаблона ограничения доступа, которые упоминаются ниже — "ДанныеТекущейОрганизации"
и "ПоОрганизацииИСчетуДУ" — уже существуют в конфигурации (используются другими документами
и регистрами). Создавать новые шаблоны не нужно, достаточно их указать по имени.


====================================================================
БЛОК 1. Документ "ОсуществлениеПраваГолосаПоЦеннымБумагам" — свойства реквизитов
====================================================================

Открыть: Конфигурация -> Документы -> ОсуществлениеПраваГолосаПоЦеннымБумагам -> Реквизиты.

1.1. Реквизит "Организация"
     - Выделить реквизит, открыть панель свойств (F4 или "Свойства" в контекстном меню).
     - Найти свойство "Заполнять из данных заполнения" (ЗаполнятьИзДанныхЗаполнения).
     - Поставить галку (включить, значение Истина).
     Зачем: чтобы общий механизм УниверсальныеМеханизмы.ЗаполнитьОбщиеРеквизитыДокумента
     корректно определял, что реквизит уже заполнен через "Ввод на основании"/данные
     заполнения, как это сделано во всех остальных документах.

1.2. Реквизит "Ответственный"
     - Свойство "Подсказка" (ToolTip) -> указать текст:
       Пользователь, ответственный за документ.

1.3. Реквизит "Комментарий"
     - Свойство "Подсказка" (ToolTip) -> указать текст:
       Произвольный комментарий.

(Пункты 1.2-1.3 — чисто косметические, не обязательны к выполнению, но приводят документ
к виду остальных документов конфигурации.)


====================================================================
БЛОК 2. Регистр сведений "ГолосованияНаСобранияхВладельцевЦенныхБумаг"
====================================================================

Открыть: Конфигурация -> Регистры сведений -> ГолосованияНаСобранияхВладельцевЦенныхБумаг
-> Измерения -> Организация.

- В панели свойств найти "Индексировать" (Indexing).
- Изменить значение с "Не индексировать" на "Индексировать".

Зачем: во всех регистрах конфигурации, где по измерению "СчетДоверительногоУправления"
настроена РЛС (см. блок 3), измерение "Организация" всегда идёт с индексацией — это
стандарт для полей, участвующих в условиях ограничения доступа и в основных отборах.


====================================================================
БЛОК 3. Права и РЛС в ролях
====================================================================

Права редактируются в конфигураторе через:
Конфигурация -> Общие -> Роли -> [Имя роли] -> двойной клик (откроется редактор прав).
В левом дереве редактора найти нужный объект (Документы -> ... / Регистры сведений -> ...).
Права отображаются таблицей чекбоксов справа. Для строк "Чтение" (и некоторых других,
поддерживающих ограничение уровня записей) в правом верхнем углу ячейки чекбокса появляется
маленький цветной индикатор/кнопка — по нему (или по кнопке "Ограничение доступа" внизу окна
редактора прав, когда выделена строка права) открывается окно ограничения доступа с текстовым
полем условия. Туда вписывается текст шаблона в виде:  #ИмяШаблона()

--------------------------------------------------------------------
3.1. Роль "ОперацииБэкОфиса"
--------------------------------------------------------------------

Объект: Документы -> ОсуществлениеПраваГолосаПоЦеннымБумагам
  - Право "Чтение" уже включено — ничего в чекбоксе менять не нужно.
  - Открыть ограничение доступа для права "Чтение" и вписать:
      #ДанныеТекущейОрганизации()
  - Остальные права (Добавление, Изменение, Проведение и т.д.) не трогать — уже верно включены.

Объект: Регистры сведений -> ГолосованияНаСобранияхВладельцевЦенныхБумаг
  - Право "Чтение" уже включено, ограничение доступа уже установлено, но с другим шаблоном.
  - Открыть ограничение доступа для права "Чтение" и ЗАМЕНИТЬ текущий текст
      #ДанныеТекущейОрганизации()
    на
      #ПоОрганизацииИСчетуДУ()
  - Остальные права (Изменение, Просмотр, Редактирование) не трогать.

--------------------------------------------------------------------
3.2. Роль "БазовыеПрава"
--------------------------------------------------------------------

Объект: Регистры сведений -> ГолосованияНаСобранияхВладельцевЦенныхБумаг
  - Право "Чтение" уже включено, ограничение доступа уже установлено.
  - Открыть ограничение доступа для права "Чтение" и ЗАМЕНИТЬ текст
      #ДанныеТекущейОрганизации()
    на
      #ПоОрганизацииИСчетуДУ()
  - Остальные права не трогать (там уже везде выключено, кроме "Чтение").

Объект: Документы -> ОсуществлениеПраваГолосаПоЦеннымБумагам
  - Сейчас у этого документа в роли "БазовыеПрава" ВСЕ права выключены (это неверно —
    пользователи с базовыми правами вообще не видят документ).
  - Поставить галку "Чтение" (включить).
  - Открыть ограничение доступа для права "Чтение" и вписать:
      #ДанныеТекущейОрганизации()
  - Все остальные права (Добавление, Изменение, Удаление, Проведение, Отмена проведения,
    интерактивные права и т.п.) оставить выключенными — как и должно быть в роли базовых
    (только просмотровых) прав.

--------------------------------------------------------------------
3.3. Роль "ОперацииБэкОфисаПросмотр"
--------------------------------------------------------------------

Объект: Регистры сведений -> ГолосованияНаСобранияхВладельцевЦенныхБумаг
  - Право "Чтение" уже включено, ограничение доступа уже установлено.
  - Открыть ограничение доступа для права "Чтение" и ЗАМЕНИТЬ текст
      #ДанныеТекущейОрганизации()
    на
      #ПоОрганизацииИСчетуДУ()
  - Право "Просмотр" не трогать (уже включено).

Объект: Документы -> ОсуществлениеПраваГолосаПоЦеннымБумагам
  - Сейчас у этого документа в роли "ОперацииБэкОфисаПросмотр" ВСЕ права выключены —
    пользователи роли просмотра бэк-офиса не видят документ в списках и не могут его открыть.
  - Поставить галки:
      Чтение            — включить
      Просмотр          — включить
      Ввод по строке    — включить
  - Открыть ограничение доступа для права "Чтение" и вписать:
      #ДанныеТекущейОрганизации()
  - Остальные права оставить выключенными (это роль "только просмотр").


====================================================================
ПОЯСНЕНИЕ: почему разные шаблоны для документа и для регистра
====================================================================

Шаблон "#ПоОрганизацииИСчетуДУ()" — стандартный для конфигурации способ ограничить доступ
по конкретному счёту доверительного управления (через регистр сведений
"ДоступныеСчетаДоверительногоУправления"). Он требует, чтобы у объекта было поле/измерение
"СчетДоверительногоУправления" непосредственно в таблице объекта.

У регистра "ГолосованияНаСобранияхВладельцевЦенныхБумаг" такое измерение есть — поэтому
для него используется именно "#ПоОрганизацииИСчетуДУ()", как и у похожих регистров
(например, "СтоимостьАктивовНеОтносящихсяКЦеннымБумагам").

У документа "ОсуществлениеПраваГолосаПоЦеннымБумагам" счёт ДУ находится в табличной части
"Клиенты" (по вашему решению — один документ на несколько счетов/клиентов сразу), а не
реквизитом шапки. Поэтому применить "#ПоОрганизацииИСчетуДУ()" к самому документу нельзя —
СУБД не найдёт нужное поле в шапке документа. Для документов, у которых нет привязки к
одному конкретному счёту ДУ (в конфигурации уже есть такой пример — документ
"АудиторскоеЗаключение"), используется более простой шаблон "#ДанныеТекущейОрганизации()" —
ограничение только по организации. Именно он и указан для документа "ОсуществлениеПраваГолоса..."
во всех трёх ролях выше.

Итог: сами голосования (записи регистра) корректно ограничены по конкретным счетам ДУ,
доступным пользователю. А документ-регистратор (шапка со списком клиентов и вопросов
повестки) виден целиком пользователям, у которых есть права на организацию — это
неизбежное следствие архитектуры "один документ на несколько клиентов", принятой ранее.


====================================================================
ПРОВЕРКА ПОСЛЕ ВНЕСЕНИЯ ИЗМЕНЕНИЙ
====================================================================

1. Сохранить конфигурацию, обновить конфигурацию базы данных.
2. Зайти под пользователем с ролью "ОперацииБэкОфисаПросмотр" (без "ОперацииБэкОфиса") —
   документ должен быть виден в списке и открываться, но недоступен для редактирования.
3. Зайти под пользователем с ролью "БазовыеПрава" (минимальный набор) — документ должен быть
   виден при наличии организации, но так же недоступен для редактирования.
4. Убедиться, что данные регистра "ГолосованияНаСобранияхВладельцевЦенныхБумаг" видны только
   по тем счетам ДУ, которые доступны пользователю (регистр
   "ДоступныеСчетаДоверительногоУправления").
