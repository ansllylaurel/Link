ИНСТРУКЦИЯ ПО РУЧНОМУ ВНЕСЕНИЮ ИЗМЕНЕНИЙ В КОНФИГУРАТОРЕ
Документ "Осуществление права голоса по ценным бумагам" и регистр сведений
"ГолосованияНаСобранияхВладельцевЦенныхБумаг".

Эта редакция инструкции учитывает 4 доработки:
  1) Исправление ошибки уникальности при проведении разных документов.
  2) RLS документа по счёту ДУ (счёт ДУ находится в табличной части).
  3) Регистрация документа во всех "универсальных" списках документов.
  4) Перенос реквизитов "Клиент" и "Вид договора" из документа в реквизиты формы.

Код модулей (модуль объекта документа и модуль формы) вы переносите копированием —
он в инструкцию не входит. Ниже только то, что нельзя скопировать текстом:
свойства объектов метаданных, состав форм и права/РЛС ролей.

ВАЖНО про порядок: сначала выполните блоки 1–3 и 5 (метаданные), затем вставьте код
модулей, затем блок 4 (права/РЛС). Форму (блок 3) настройте до вставки кода формы.


====================================================================
БЛОК 1. Регистр сведений "ГолосованияНаСобранияхВладельцевЦенныхБумаг"
        (исправление ошибки уникальности — пункт 1)
====================================================================

Причина ошибки "Запись с такими ключевыми полями существует":
у регистра сведений ключом уникальности являются ПЕРИОД + ИЗМЕРЕНИЯ.
РЕГИСТРАТОР (документ) в ключ уникальности НЕ входит. Поэтому два разных документа
с одинаковым набором (период + организация + ценная бумага + счёт ДУ + номер вопроса)
конфликтуют. Чтобы каждый документ имел собственные независимые записи, добавляется
измерение "Документ".

Открыть: Регистры сведений -> ГолосованияНаСобранияхВладельцевЦенныхБумаг -> Измерения.

1.1. Добавить новое измерение:
     - Имя:            Документ
     - Синоним:        Документ
     - Тип:            ДокументСсылка.ОсуществлениеПраваГолосаПоЦеннымБумагам
     - Ведущее:        нет (снять)
     - Основной отбор: да
     - Индексировать:  Индексировать
     - Заполнять проверку заполнения / запрет незаполненных значений — не требуется.

1.2. (если ещё не сделано ранее) Измерение "Организация" -> Индексировать = "Индексировать".

Заполнение измерения "Документ" выполняется в коде модуля объекта (Движение.Документ = Ссылка),
этот код вы переносите вместе с модулем.


====================================================================
БЛОК 2. Документ "ОсуществлениеПраваГолосаПоЦеннымБумагам"
        (перенос реквизитов из документа — пункт 4)
====================================================================

Открыть: Документы -> ОсуществлениеПраваГолосаПоЦеннымБумагам -> Табличные части -> Клиенты.

2.1. Удалить из табличной части "Клиенты" два реквизита:
     - Клиент
     - ВидДоговора
     Оставить только реквизит "СчетДоверительногоУправления".
     (Хранить клиента и вид договора в документе не нужно — это расчётные данные,
      они будут показываться на форме как реквизиты формы, см. блок 3.)

2.2. (справочно, если не сделано ранее) Реквизит шапки "Организация":
     "Заполнять из данных заполнения" = включено.

2.3. (необязательно) Нумератор. Сейчас документ использует нумератор "ОперацииБэкОфиса".
     Документ не является операцией бэк-офиса; при желании можно завести отдельный
     нумератор или включить собственную автонумерацию. На работу это не влияет —
     оставить как есть тоже допустимо.

ЗАМЕЧАНИЕ по журналу операций (пункт 1): в модуле объекта убраны вызовы
РаботаСДокументами.* и РаботаСЖурналамиОпераций.* — документ больше не проводится
через механизм бэк-офиса. Дополнительно документ НЕ входит в перечисление
"ВидыОперацийБэкОфиса", поэтому в журнал операций бэк-офиса он не попадает. Ничего
удалять из перечисления не нужно — просто убедитесь, что документа там нет.


====================================================================
БЛОК 3. Форма документа "ФормаДокумента"
        (реквизиты формы вместо реквизитов документа — пункт 4)
====================================================================

Открыть: Документы -> ОсуществлениеПраваГолосаПоЦеннымБумагам -> Формы -> ФормаДокумента.

3.1. Добавить РЕКВИЗИТ ФОРМЫ (вкладка "Реквизиты" редактора формы):
     - Имя:  Клиенты
     - Тип:  ТаблицаЗначений
     Внутри этого реквизита добавить колонки:
       1) СчетДоверительногоУправления — тип СправочникСсылка.СчетаДоверительногоУправления
       2) Клиент                       — тип СправочникСсылка.ЮрФизЛица
       3) ВидДоговора                  — тип ПеречислениеСсылка.ВидыДоговоровДоверительногоУправления

3.2. Таблица "Клиенты" на форме (элемент формы):
     - Свойство "ПутьКДанным" (DataPath) переключить с "Объект.Клиенты" на "Клиенты"
       (на новый реквизит формы — таблицу значений).
     - Колонки таблицы перепривязать:
         * КлиентыСчетДоверительногоУправления -> ПутьКДанным = Клиенты.СчетДоверительногоУправления
         * КлиентыКлиент                       -> ПутьКДанным = Клиенты.Клиент,       ТолькоПросмотр = Да
         * КлиентыВидДоговора                  -> ПутьКДанным = Клиенты.ВидДоговора,  ТолькоПросмотр = Да
     - (желательно) У колонки "КлиентыСчетДоверительногоУправления" настроить связь
       параметров выбора: Отбор.Организация = Объект.Организация (как было у реквизита ТЧ).

3.3. События формы и элементов (вкладка "События"):
     - Форма, событие "ПриЧтенииНаСервере"     -> ПриЧтенииНаСервере
     - Форма, событие "ПередЗаписьюНаСервере"  -> ПередЗаписьюНаСервере
       (событие "ПриСозданииНаСервере" уже назначено на ПриСозданииНаСервере)
     - Поле "ДатаГолосования", событие "ПриИзменении" -> ДатаГолосованияПриИзменении
     - Колонка "КлиентыСчетДоверительногоУправления", событие "ПриИзменении"
                                              -> КлиентыСчетДоверительногоУправленияПриИзменении

3.4. После настройки формы вставьте код модуля формы (копированием).
     Логика: при открытии счета ДУ переносятся из документа в таблицу формы и
     достраиваются расчётные колонки (клиент, вид договора); при записи в документ
     сохраняется только счёт ДУ.


====================================================================
БЛОК 4. Права и РЛС в ролях (RLS по счёту ДУ — пункт 2)
====================================================================

Задача: ограничить доступ к документу по счёту ДУ. Счёт ДУ находится в табличной
части "Клиенты", поэтому стандартный шаблон "ПоОрганизацииИСчетуДУ" (он требует поле
"СчетДоверительногоУправления" в шапке) напрямую не подходит. Используется тот же
подход, что и у документов "ВходящийДокумент"/"ИсходящийДокумент", где счета ДУ тоже
лежат в табличной части: заводится отдельный шаблон ограничения, который проверяет,
что среди строк табличной части НЕТ ни одного счёта ДУ, недоступного пользователю.

Изменения нужно внести в 3 роли: ОперацииБэкОфиса, БазовыеПрава, ОперацииБэкОфисаПросмотр.

4.1. В КАЖДОЙ из этих трёх ролей добавить новый шаблон ограничения доступа.
     Роль -> вкладка "Шаблоны ограничений" -> Добавить.
       Имя шаблона: ОсуществлениеПраваГолосаПоЦБ
       Текст шаблона (вставить целиком; символы & набираются как обычный амперсанд):

#Если НЕ &ЭтоФоновоеЗадание #Тогда
		ТекущаяТаблица
	ИЗ
		#ТекущаяТаблица КАК ТекущаяТаблица
	ГДЕ
	#Если &КонтрольДоступаКСчетамДоверительногоУправления И НЕ &ДоступныВсеСчетаДоверительногоУправления #Тогда
		ТекущаяТаблица.Организация = &ТекущаяОрганизация
	И НЕ 1 В
				(ВЫБРАТЬ ПЕРВЫЕ 1
					1
				ИЗ
					Документ.ОсуществлениеПраваГолосаПоЦеннымБумагам.Клиенты КАК Клиенты
				ГДЕ
					Клиенты.Ссылка = ТекущаяТаблица.Ссылка
					И Клиенты.СчетДоверительногоУправления В
						(ВЫБРАТЬ
							СчетаДУ.Ссылка КАК Ссылка
						ИЗ
							Справочник.СчетаДоверительногоУправления КАК СчетаДУ
						ГДЕ
							СчетаДУ.Организация = &ТекущаяОрганизация
							И НЕ СчетаДУ.Ссылка В
									(ВЫБРАТЬ
										ДоступныеСчетаДоверительногоУправления.СчетДоверительногоУправления
									ИЗ
										РегистрСведений.ДоступныеСчетаДоверительногоУправления КАК ДоступныеСчетаДоверительногоУправления
									ГДЕ
										ДоступныеСчетаДоверительногоУправления.Пользователь = &ТекущийПользователь)))
	#Иначе
		ТекущаяТаблица.Организация = &ТекущаяОрганизация
	#КонецЕсли
#КонецЕсли

4.2. В КАЖДОЙ из трёх ролей у документа "ОсуществлениеПраваГолосаПоЦеннымБумагам"
     для права "Чтение" открыть ограничение доступа и указать условие:
        #ОсуществлениеПраваГолосаПоЦБ()
     (заменить ранее стоявшее там #ДанныеТекущейОрганизации()).

4.3. Про выбор полей в окне ограничения доступа:
     список полей оставить ПУСТЫМ (ничего не отмечать). Ограничение действует на
     уровне записи целиком — так же, как у всех остальных объектов конфигурации.

4.4. Регистр сведений "ГолосованияНаСобранияхВладельцевЦенныхБумаг" (если не сделано ранее):
     право "Чтение" -> ограничение доступа -> #ПоОрганизацииИСчетуДУ()
     (в этих же трёх ролях; у регистра счёт ДУ есть в измерениях, поэтому здесь
      используется стандартный шаблон).

Как это работает: сами записи голосований (регистр) ограничены по конкретным
доступным счетам ДУ. Документ виден пользователю, только если ВСЕ счета ДУ в его
табличной части доступны пользователю (и организация совпадает) — стандартное
поведение для документов со счетами ДУ в табличной части.


====================================================================
БЛОК 5. Регистрация документа в "универсальных" списках (пункт 3)
====================================================================

Добавить тип ДокументСсылка.ОсуществлениеПраваГолосаПоЦеннымБумагам (или сам документ)
в следующие объекты. Порядок в списках значения не имеет.

5.1. Определяемый тип "ВсеТипы"
     Общие -> Определяемые типы -> ВсеТипы -> Тип -> добавить составной тип
     ДокументСсылка.ОсуществлениеПраваГолосаПоЦеннымБумагам.

5.2. Общие команды (для каждой: свойство "Тип параметра команды" -> добавить
     ДокументСсылка.ОсуществлениеПраваГолосаПоЦеннымБумагам):
       - Общие команды -> ДвиженияДокумента
       - Общие команды -> СтруктураПодчиненности
       - Общие команды -> ОткрытьФормуПерейти

5.3. Регистр сведений "ЗначенияДополнительныхСведений", команда "ДополнительныеСведенияОбъекта"
     -> свойство "Тип параметра команды" -> добавить
     ДокументСсылка.ОсуществлениеПраваГолосаПоЦеннымБумагам.
     (Чтобы на форме документа была доступна команда "Дополнительные сведения".)

5.4. Уже настроено ранее, проверять не обязательно:
       - Подсистема "Ценные бумаги" (Состав) — документ есть.
       - Определяемый тип "ВладелецПрисоединенныхФайлов" — документ есть
         (команда "Присоединенные файлы" / "скрепка" работает через него).
       - Состав конфигурации, роли.

5.5. (необязательно) Порядок команд в панели навигации подсистемы "Ценные бумаги":
     Подсистемы -> ... -> ЦенныеБумаги -> Командный интерфейс ->
     добавить команду открытия списка документа в нужное место.

Куда добавлять НЕ нужно (специально проверено): нет отдельного критерия отбора
"СтруктураПодчиненности" (это общая команда, см. 5.2); журналы документов тематические,
общего журнала нет; бухгалтерские команды/подписки не нужны (документ не делает
бухгалтерских проводок и не является операцией бэк-офиса).


====================================================================
ПРОВЕРКА ПОСЛЕ ВНЕСЕНИЯ ИЗМЕНЕНИЙ
====================================================================

1. Обновить конфигурацию базы данных, при необходимости — реструктуризация регистра
   (добавлено измерение "Документ").
2. Провести два разных документа голосования с пересекающимися счетами/бумагой/датами —
   ошибка уникальности больше не возникает (движения разделяются по измерению "Документ").
3. Открыть документ: в таблице "Клиенты" видны счёт ДУ, клиент и вид договора; при этом
   клиент и вид договора не сохраняются в документе (только счёт ДУ).
4. Под пользователем с ограниченным доступом к счетам ДУ убедиться, что документ виден,
   только если все его счета ДУ доступны пользователю; данные регистра видны лишь по
   доступным счетам ДУ.
5. На форме документа доступны команды "Движения документа", "Структура подчинённости",
   "Перейти", "Дополнительные сведения".
