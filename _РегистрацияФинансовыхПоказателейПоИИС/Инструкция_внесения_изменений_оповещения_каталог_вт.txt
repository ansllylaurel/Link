ИЗМЕНЕНИЕ 1. Замена прямой отправки писем на универсальный механизм оповещений
================================================================================
Область: вся обработка (3 места)
Причина: вместо жёсткой привязки к конкретным адресам и функции
         РаботаСЭлектроннойПочтой используется справочник «Оповещения»,
         где администратор задаёт шаблон и получателей.
         Шаблоны будут созданы отдельно при настройке.

Паттерн: формируем структуру РеквизитыОповещения (поля используются
         шаблоном оповещения для подстановки), затем вызываем:
         Справочники.Оповещения.СформироватьОповещения(
             "<ИдентификаторДействия>",
             Перечисления.ТипыСобытий.ВнешнийВызов,
             РеквизитыОповещения)

----------
1а. Основной отчёт (в конце процедуры ОтправитьОтчет)
----------
БЫЛО:
    ТемаПисьма = Строка(ЭтотОбъект.Организация.Наименование) + ". Регистрация...";

    ТелоПисьма = Новый ТекстовыйДокумент;
    ТелоПисьма.Прочитать(ИмяВременногоФайла);

    ПараметрыПисьма = Новый Структура("Кому, Тема, Тело, ТипТекста, Вложения",
        ПолучателиОповещения, ТемаПисьма, ТелоПисьма.ПолучитьТекст(),
        ТипТекстаПочтовогоСообщения.HTML, Вложения);

    РаботаСЭлектроннойПочтой.ОтправитьЭлектронноеПисьмо(
        РаботаСЭлектроннойПочтой.ПолучитьСистемнуюУчетнуюЗапись(), ПараметрыПисьма);

СТАЛО:
    ТелоПисьма = Новый ТекстовыйДокумент;
    ТелоПисьма.Прочитать(ИмяВременногоФайла);

    РеквизитыОповещения = Новый Структура;
    РеквизитыОповещения.Вставить("Организация", ЭтотОбъект.Организация);
    РеквизитыОповещения.Вставить("Период",      ЭтотОбъект.Период);
    РеквизитыОповещения.Вставить("Тело",        ТелоПисьма.ПолучитьТекст());
    РеквизитыОповещения.Вставить("Вложения",    Вложения);

    Справочники.Оповещения.СформироватьОповещения(
        "Обработка._РегістрацияФинансовыхПоказателейПоИИС.ОтправитьОтчет()",
        Перечисления.ТипыСобытий.ВнешнийВызов,
        РеквизитыОповещения);

    Функция ПолучитьБазовыйКаталогДоходности()

        //TODO Заменить

  - Добавить строковое дополнительное сведение с ключом:

ИЗМЕНЕНИЕ 3. Замена пакетного запроса на раздельные запросы с временными таблицами
================================================================================
Причина: пакетный запрос (ВыполнитьПакет) возвращает массив, а элементы
         выбираются по числовому индексу (Пакет[1], Пакет[2]), что снижает
         читаемость. Замена на раздельные именованные запросы через общий
         МенеджерВременныхТаблиц устраняет привязку к индексам и делает
         код согласованным с остальными функциями обработки
         (РассчитатьИЗарегистрироватьФинансовыеПоказатели уже так устроена).

----------
3а. Функция ПолучитьПакетДляДоходности переименована и переписана
----------
БЫЛО (сигнатура):
    Функция ПолучитьПакетДляДоходности()
        Запрос = Новый Запрос;
        Запрос.Текст = "... <3 запроса через ;> ...";
        Возврат Запрос.ВыполнитьПакет();
    КонецФункции

СТАЛО (сигнатура):
    Функция ПолучитьДанныеДляДоходности()

Структура нового тела:
  1) МВТ = Новый МенеджерВременныхТаблиц;

  2) ЗапросСтратегии  — создаёт временную таблицу _СтандартныеСтратегии
     (тот же текст, что был в первом пакете; теперь обращение к МВТ явное)
     ЗапросСтратегии.Выполнить()  ← результат не нужен, только заполняем МВТ

  3) ЗапросОтчёта  — использует _СтандартныеСтратегии,
     выбирает показатели для печатной формы (левое соединение + ИТОГИ по Стратегия)
     ПоказателиОтчёта = ЗапросОтчёта.Выполнить()

  4) ЗапросXML  — использует _СтандартныеСтратегии,
     выбирает все периодические показатели для XML-файлов
     ПоказателиXML = ЗапросXML.Выполнить()

  5) Возврат Новый Структура с полями:
        "ПоказателиОтчёта"  — РезультатЗапроса (был Пакет[1])
        "ПоказателиXML"     — РезультатЗапроса (был Пакет[2])

----------
3б. Обновлены вызовы в процедуре ОтправитьОтчет
----------
БЫЛО:
    Пакет = ПолучитьПакетДляДоходности();
    ...
    ВыборкаСтратегии = Пакет[1].Выбрать(ОбходРезультатаЗапроса.ПоГруппировкам);
    ...
    Вложения = СформироватьXMLВложенияПоСтратегиям(Пакет);

СТАЛО:
    ДанныеДоходности = ПолучитьДанныеДляДоходности();
    ...
    ВыборкаСтратегии = ДанныеДоходности.ПоказателиОтчёта.Выбрать(ОбходРезультатаЗапроса.ПоГруппировкам);
    ...
    Вложения = СформироватьXMLВложенияПоСтратегиям(ДанныеДоходности.ПоказателиXML);

----------
3в. Обновлена функция СформироватьXMLВложенияПоСтратегиям
----------
БЫЛО:
    Функция СформироватьXMLВложенияПоСтратегиям(Пакет)
        ...
        ВыборкаСтратегии = Пакет[2].Выбрать(ОбходРезультатаЗапроса.ПоГруппировкам);

СТАЛО:
    Функция СформироватьXMLВложенияПоСтратегиям(РезультатЗапросаXML)
        ...
        ВыборкаСтратегии = РезультатЗапросаXML.Выбрать(ОбходРезультатаЗапроса.ПоГруппировкам);

ДОПОЛНИТЕЛЬНЫЕ ДЕЙСТВИЯ ДО ПУБЛИКАЦИИ
================================================================================
1. Создать три шаблона в справочнике «Оповещения» с идентификаторами:
       Обработка._РегістрацияФинансовыхПоказателейПоИИС.ОтправитьОтчет()
       Обработка._РегістрацияФинансовыхПоказателейПоИИС.РасхожденияВФайлах()
       Обработка._РегістрацияФинансовыхПоказателейПоИИС.РазмещениеДоходностиНаСайте()
   Тип события для всех: ВнешнийВызов
   Доступные реквизиты для подстановки в шаблон:
       ОтправитьОтчет()         → Организация, Период, Тело, Вложения
       РасхожденияВФайлах()     → Организация, Период, ТекстПисьма
       РазмещениеДоходностиНаСайте() → Организация, Период, ТекстПисьма

2. Заполнить дополнительное сведение организации:
       Ключ:    ВнешниеОбработки._РегістрацияФинансовыхПоказателейПоИИС.КаталогФайловДоходности
       Значение: UNC-путь к сетевой папке с файлами доходности

ЧЕКЛИСТ ПРОВЕРКИ
================================================================================
[ ] В ObjectModule.bsl нет ни одного вызова РаботаСЭлектроннойПочтой.ОтправитьЭлектронноеПисьмо
[ ] В ObjectModule.bsl нет ни одного вызова ПолучитьПакетДляДоходности или ВыполнитьПакет
[ ] В ObjectModule.bsl нет обращения Пакет[0], Пакет[1], Пакет[2]
[ ] Функция ПолучитьБазовыйКаталогДоходности не содержит хардкодированных путей
[ ] Три оповещения созданы в справочнике Оповещения
[ ] Дополнительное сведение по организации заполнено корректным UNC-путём
[ ] Обработка запускается без ошибок на тестовом периоде
